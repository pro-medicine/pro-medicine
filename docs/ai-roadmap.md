# 약쏙 AI 기능 로드맵 (담당: 영준)

> 기준일: 2026-10-26. 결정이 바뀌면 이 문서를 먼저 고친다.
> 표기: **F** = 기능, **Data** = 그 버전에 필요한 데이터 준비. 각 버전은 앞 버전 위에 쌓인다.

## 확정된 방향

- 추천의 기본은 **성분 추천**이다. 제품은 판매하지 않는다.
- 제품 데이터(식약처 건강기능식품)는 **내부 검증용으로만 보유**하고 사용자에게 목록으로 노출하지 않는다.
- 제품 추천 흐름: **부족 성분 → 약사 크리에이터 리뷰 종합 → 리뷰 속 제품을 우리 DB와 매칭 → 2차 안전 필터 → 통과한 제품만 노출**
  - 후보는 리뷰에서, 검증은 우리 DB 규칙으로, 설명은 LLM으로
  - DB 매칭 실패·성분 미상 = "안전"이 아니라 **추천 제외**
  - 안전 문구는 보장 표현 금지. "입력하신 약·질환 기준으로 주의 성분이 확인되지 않았어요. 복용 전 의사·약사와 상담하세요" 형태
- 안전 판단은 LLM이 하지 않는다. 규칙 테이블이 사전(프롬프트 금지 목록)·사후(최종 차단)로 두 번 막는다.
- 약 이름을 모르고 계열만 아는 경우("혈압약"): 해당 성분을 **추천하되 그 성분에만 의사·약사 상담 경고(WARN)**. 정확한 약을 알면 기존 규칙(EXCLUDE 등) 적용.
- 벡터 저장: **MySQL + 애플리케이션에서 코사인 유사도 계산** (커뮤니티판 MySQL은 DISTANCE()·벡터 인덱스 없음). Spring AI `VectorStore` 인터페이스로 감싸 교체 가능하게.
- 유튜브 수집: **로컬 PC에서 월 1회 배치** → 서버 DB 업로드 (클라우드 IP 차단 회피). PoC 8/8 성공 (2026-10-26).
- 제외·후순위: 커뮤니티 RAG, 장바구니, 최소 제품 조합 알고리즘(충족률 표시로 대체), 별도 맞춤 질문 화면(대화창 되묻기로 흡수)

## Version 1 — 설문 → 영양성분 추천

**목표**: 완성된 추천 API(V4 파이프라인)를 화면까지 연결해서 설문 → 성분 추천 흐름을 완성한다.

### 기능
| ID | 기능 | 내용 | 백엔드 상태 |
|---|---|---|---|
| F1-1 | 설문 | 설문 API로 문항 로드, 회원·비회원 분기(민감 문항은 회원+동의), 임신은 매번 묻기 | ✅ API 완료 |
| F1-2 | 추천 요청·로딩 | `POST /recommendations`, sync 기본 + queue(PENDING → 폴링) 대응 | ✅ API 완료 |
| F1-3 | 결과 | 성분 카드: 성분, 추가 섭취량, 현재 섭취량, 이유, 성분별 경고 | ✅ API 완료 |
| F1-4 | 제외 성분 | `excludedItems`와 이유 (1차 필터 결과) | ✅ API 완료 |
| F1-5 | 예외 처리 | 폴백(`RULE_ONLY`, `notice`), 에러, 빈 결과, 타임아웃, 의학적 조언 아님 문구, "설문·건강 프로필에 입력한 약 기준" 안내 | ✅ API 완료 |
| F1-6 | 최근 결과 재진입 | `/users/me/recommendations/latest` | ✅ API 완료 |
| F1-7 | 확장 자리 | 성분 카드에 "제품 추천 보기" 버튼 (비활성, V3에서 활성화) | 화면 |
| F1-8 | 버그·운영 | **타임아웃 미연결**(30초 설정 → 실제 60초에 끊김) 수정, `/actuator/prometheus` 노출 확인(설정 있음) | 🔴 타임아웃 미해결 |

### 데이터 준비
| ID | 작업 | 내용 | 상태 |
|---|---|---|---|
| Data1-1 | `schema.sql` 정리 | 엔티티와 불일치(`health_surveys`/`survey_id` 구조, 신규 테이블 누락, `DROP TABLE` 포함). 엔티티 기준으로 구조만 덤프해 교체, 기존 로컬 DB는 재생성 + 시드 | 🔴 미해결 (🤝 팀) |
| Data1-2 | 약 정보 기준 | V1은 **설문·건강 프로필(`user_medications`)이 기준**. `user_products`는 V2에서 통합 | ✅ 결정 |
| Data1-4 | 추천 성분 코드화 | V1 파이프라인부터 `ingredient_name`에 성분 코드 저장 | ✅ 완료 |
| Data1-5 | 약 계열 모름 | `drugs`에 "혈압약 (이름 모름)" 등 8개(D-U01~U08), 규칙 12개(R-U*) 추가. 새 DB는 STEP02·STEP07 시드에 포함, 기존 DB는 `docs/sql/STEP12_seed_unknown_drug_classes.sql` | ✅ 시드 추가 (테스트 로컬 확인 필요) |

### 완료 기준

### 측정·모니터링

## Version 2 — 내 복용 제품 기반 정확한 추천

**목표**: 먹고 있는 제품을 등록하면 성분·함량이 자동으로 채워지고, 부족분과 과다 섭취를 정확히 계산한다.

### 기능
| ID | 기능 | 내용 |
|---|---|---|
| F2-1 | 복용 제품 등록 | 제품명 검색 → 선택 → 성분·함량 자동 반영. 실패 시 수동 입력(섭취량 "모름") |
| F2-2 | 실제 복용량 | 라벨과 다르게 먹는 경우 (`daily_servings`, 비면 라벨 값) |
| F2-3 | 추천에 섭취량 연결 | 성분 추천의 "현재 섭취량"에 복용 제품 합산값 사용 |
| F2-4 | 과다·중복 섭취 분석 | 성분 합산 → 상한 대비 %(서버 계산) + 금기 체크(`RuleEngine`) + LLM 쉬운 설명 |
| F2-5 | 화면 | 복용 제품 등록·목록, 섭취 분석 결과 |

### 데이터 준비
| ID | 작업 | 내용 |
|---|---|---|
| Data2-1 | 제품 테이블 확장 | `catalog_products`에 1회 분량, 1일 섭취 횟수, 기준일 + `product_ingredient`(제품, 성분 코드, 1회 함량 NULL 허용, 단위, 출처) |
| Data2-2 | 식약처 영양성분 import | 빈칸 → `NULL`(모름), 0은 0, 단위 변환(μg↔IU, 1μg=40IU), 하루 섭취량 = 1회 함량 × 1일 섭취 횟수, 같은 제품 중복 신고 정리, 품목제조신고번호로 연결 |
| Data2-3 | 원재료 → 성분 코드 | 영양성분 컬럼에 없는 기능성 원료(오메가3, 은행잎 등)를 LLM 구조화 추출. 정답셋 30~50개로 정확도 측정, 확신 낮은 건 검수 |
| Data2-4 | 제품명 검색 | 제품명 정규화 + MySQL `FULLTEXT`(ngram). 안 잡히면 제품명 임베딩 검색 |
| Data2-5 | 성분 코드 확장 | 현재 14개 → 오메가3, 루테인, B6 등 (V2.5에서 24개로 확장). enum, LLM 스키마, 프롬프트, 기준표·규칙 시드, 골든 테스트 같이 수정 |
| Data2-6 | 약 정보 통합 | `user_products`(MEDICINE, 자유 입력)와 `user_medications`(`drug_id`) 기준 통일. 복용 목록에서 약 등록 시 `drugs` 검색 → `user_medications`에도 저장 |

### 참고 (식약처 데이터 한계)
- 영양성분 컬럼: 칼슘, 철, 인, 칼륨, 나트륨, 비타민A·C·D, 베타카로틴, B1, B2, 나이아신 등 기본 영양소 위주
- **B12, 비타민K, 엽산, 마그네슘, 아연 컬럼 없음** → 함량 NULL, "들어 있음"은 Data2-3으로 채움

### 완료 기준
- 제품 등록 → 추천 결과의 현재 섭취량이 바뀜
- 상한 초과·금기 조합에서 경고 확인

### 측정
- 제품명 검색 `LIKE` vs `FULLTEXT` 지연·Top-1 정확도, 원재료 추출 precision/recall

## Version 2.5 — 성분 코드 확장 (14 → 24개)

**목표**: 성분 추천(V1·V2)이 고를 수 있는 성분을 늘려, 리뷰에 많이 나오는 오메가3·유산균 같은 제품이 V3에서 카드로 나올 수 있게 한다. 기존 기능·구조는 그대로, **성분 종류만 늘린다** (테이블·컬럼·화면 변경 없음).

### 기능
| ID | 기능 | 내용 | 상태 |
|---|---|---|---|
| F2.5-1 | 성분 10개 추가 | 오메가3, 프로바이오틱스(억 CFU), 커큐민, 코엔자임 Q10, 콜라겐, 글루코사민, 나이아신(mg NE), 밀크씨슬, 루테인, 비타민 B6. 약사 영상 1,000개 제목·설명란 빈도 + 식약처 건강기능식품 원료 여부로 선정 (베르베린·NAC·멜라토닌 제외, 홍삼은 다음 1순위) | ✅ enum·스키마·프롬프트 버전(v1.2·v2.2·v4.3) |
| F2.5-2 | 안전 규칙 | 회원 32개(기본 WARN, "피할 것"이나 애매하면 EXCLUDE, 이름 아는 약 + 계열 모름 둘 다) + 비회원 8개(회원 EXCLUDE 성분 전부 제외). 출처 S-21~S-30 | ✅ 시드 (약사 검토 전) |
| F2.5-3 | 약물 계열 5개 | 항혈소판제, 인슐린, 항암제, 면역억제제, 뇌전증약 (대표 약 + 이름 모름 8행) | ✅ 시드 |
| F2.5-4 | 기준값 | 나이아신·비타민 B6(NIH-ODS), 오메가3 상한 5000mg. 기능성 원료 7개와 오메가3 권장 범위는 식약처 공전 원문 확보 전이라 TODO("기준값 미등록") | 🟡 일부 |

### 완료 기준
- `RuleEngineTest` 새 규칙 케이스(조건 있음 → 경고·제외, 없음 → 통과, 비회원 8개 제외·오메가3·B6 통과) 통과
- 골든: 출력 스키마 성분 목록 24개, 기존 14개 성분 동작 변화 없음, 기존 테스트 통과

### 남은 일
- 리뷰 파이프라인(레포 밖) 매핑: `extract_spec.py` 성분 코드, `resolve_products.py`의 DSLD `GROUP_CODE`·식약처 `I0030_PREFIX` (유산균 CFU 변환 포함) → V3로
- 기능성 원료 기준값 화면 문구("권장 섭취 범위") 채원님 결과 화면과 협의, 서비스 공개 전 약사 검토 + 식약처 고시 원문 대조(S-30)

## Version 3 — 약사 리뷰 기반 안전 제품 추천

**목표**: 부족 성분에 대해 약사 크리에이터 리뷰를 종합해 제품을 추천하고, 우리 DB로 안전을 확인한 제품만 보여준다.

### 기능
| ID | 기능 | 내용 |
|---|---|---|
| F3-1 | 성분별 추천 제품 집계 | 리뷰 추출 결과를 SQL로 집계 (추천한 약사 수, 평가) |
| F3-2 | 2차 안전 필터 | 매칭 실패·성분 미상 제외 → 제품 전체 성분 금기 체크 + 현재 섭취량 합산 상한 체크 |
| F3-3 | 순위·충족률 | 추천 약사 수, 평가, 함량 적합도, 협찬 감점 / "비타민D 100%, 칼슘 40%" |
| F3-4 | 리뷰 요약·비교 설명 | 장단점, 먹는 법, 추천 대상, 근거 영상 링크·시각. 숫자는 서버, 문장은 LLM |
| F3-5 | 대체 제품 | 금기로 빠진 제품과 이유 + 통과한 다른 크리에이터 추천 제품 |
| F3-6 | 안전 문구 | 확인 기준 명시 + 상담 권고 |
| F3-7 | 화면 | V1 "제품 추천 보기" 활성화 → 제품 추천 화면 |

### 데이터 준비
| ID | 작업 | 내용 |
|---|---|---|
| Data3-1 | 약사 채널 화이트리스트 | 10~20개 채널, 테이블로 관리 |
| Data3-2 | 수집 배치 (로컬, 월 1회) | 공식 YouTube Data API(검색, 제목·설명, 협찬 여부, 댓글) + 자막(youtube-transcript-api, 개인 PC). 차단 시 유료 API로 교체 가능하게 인터페이스 분리 |
| Data3-3 | 리뷰 구조화 추출 | LLM: 추천 제품, 성분, 추천/비추천, 장단점, 먹는 법, 추천 대상, 영상 시각. 자동 자막 오인식(예: GNC→GNN)은 제목·설명란으로 보정 |
| Data3-4 | 제품 매칭 | 리뷰 속 제품명 → 우리 DB (Data2-4 재사용, 유통·수입업체명 함께 사용) |
| Data3-5 | 리뷰 요약 사전 생성 | 제품별 요약을 수집 때 미리 생성 (응답 시 LLM 호출 제거) |
| Data3-6 | 서버 업로드 | `video_id` 기준 upsert, 트랜잭션, 수집일 기록, 삭제 영상 비활성. 자막 원문은 Git 금지 |

### 저장 구조
| 단계 | 테이블(예) | 용도 | 임베딩 |
|---|---|---|---|
| 원문 | `review_video` | 재처리용 | ✗ |
| 구조화 추출 | `review_mention` | 제품 추천 집계 | ✗ |
| 청크 | `review_chunk` (`ingredient_code` 필수, `product_id` nullable) | V4 대화 RAG | ✓ |

### 완료 기준
- 부족 성분 → 안전한 제품 Top N + 근거 영상
- 금기 성분 포함 제품이 노출되지 않음을 테스트로 보장

### 측정
- 리뷰 요약 사전 생성 vs 요청 시 생성 (지연·비용)
- 2차 필터 차단율, 안전 확인 불가 비율, 제품 매칭률, 수집 성공률, 데이터 신선도
