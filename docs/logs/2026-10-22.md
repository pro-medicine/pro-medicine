## 건강 정보 조회/수정 API 동작 확인 (주연, Claude Code, 이슈 #13)

- 앱 재시작 시 `Port 8080 already in use`: 10:22에 실행된 앱이 이미 떠 있었음 (새 코드 포함), 그 앱으로 테스트
- 로컬 DB `users`가 비어 있고 `user_id`에 AUTO_INCREMENT가 없음 (1364 에러) → 오늘 테이블이 다른 SQL로 다시 만들어진 것으로 보임, 테스트 유저는 `user_id = 1` 직접 지정해 넣음(예시 데이터)
- `/api/v1/users/{userId}/health-profile`
  - 미입력 GET → 200, 모든 값 null
  - PUT(생성) → 200, 저장 값 + updatedAt / 이후 GET 같은 값
  - 일부 항목만 PUT → 나머지 null로 교체 (전체 교체 방식 확인)
  - 키 -5 / 출생연도 1800 / 성별 11자 → `E002`, HTTP 502 (공통 `INVALID_INPUT` 상태값 문제)
  - 없는 유저 GET/PUT → 404 `U001`
- 참고: PUT 응답의 updatedAt은 소수점 초까지, GET은 DB DATETIME이라 초 단위
- 협의 필요: 로컬 DB `users.user_id` AUTO_INCREMENT 누락 원인과 기준 스키마 파일 통일

## PR #13 리뷰 반영: 키·몸무게 범위 검증, INVALID_INPUT 400 (주연, Claude Code, 이슈 #13)

- 리뷰 1: `height`, `weight`가 DECIMAL(5,1)인데 양수만 검사 → 170.55는 반올림 저장, 10000.0은 저장 실패 가능
  - `HealthProfileService.isPositive` → `isValidMeasure`: 0 초과, 소수점 아래 1자리 이하(`stripTrailingZeros` 후), 최대 9999.9
  - 저장 시 `setScale(1)`로 자릿수 통일 → PUT 응답과 GET 값 일치 (170.50 → 170.5, 163 → 163.0)
- 리뷰 2: 공통 `ErrorCode.INVALID_INPUT`을 `BAD_GATEWAY`(502) → `BAD_REQUEST`(400)로 변경 (사용처: 건강 정보 저장, 닉네임 변경)
- 테스트(앱 재시작 후)
  - 200: 170.5, 170.50, 9999.9, 163 / PUT 응답과 GET 값 동일 확인
  - 400 `E002`: 170.55, 10000.0, -5, 0, 몸무게 51.55, 출생연도 1800, 닉네임 공백
  - 404 `U001`: 없는 유저
- 테스트 후 데이터 원복(키 163.0, 몸무게 51.5)
- IntelliJ 경고 정리: `setScale(1)` → `setScale(1, RoundingMode.UNNECESSARY)`(의도 명시, 동작 동일), `isValidMeasure` → `isInvalidMeasure`로 조건을 뒤집어 `!` 없이 사용(동작 동일)
