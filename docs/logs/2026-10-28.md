
## V2 질문 대기 방식 A/B 두 버전 준비 (영준, Claude)

- 질문: 미리 만들기는 효과가 없었는지, 비용이 정말 가장 적었는지
  - 설명: 답 → 다음 질문 대기는 줄었음(B안 p50 4.4초 → 0.0초)
  - 대신 묶음 호출이 느려 첫 질문이 6.3초 → 12.2초로 늦어지고, 회차 전체 대기 합계는 비슷함
  - 호출 수는 적지만 묶음 출력이 길고 버리는 질문이 있어 비용 +31%
- 요청: 전체 대기가 길어도 질문이 바로바로 오는 쪽이 사용자 경험이 나을 수 있음 → 두 버전을 준비하고, 사용자 조사 후 결정. docs에 남김
- 변경 파일
  - `backend/src/main/resources/application-pq-upfront.yml`(새로): B안 프로필, `pq.prefetch-strategy: UPFRONT_FOLLOWUP`
  - `docs/design/V2-question-prefetch-options.md`(새로): 두 버전 비교(10-27 측정값과 출처), 바꾸는 법, 사용자 조사 질문·판단 기준 제안, B안 선택 시 협의 사항, 한계
  - `backend/docs/api/personalized-api.md`: 설정 표 아래 비교 문서 링크 1줄
- 기본값은 그대로 A안(`NONE`). 이중 요청은 끔 그대로
- 확인: 로컬 전용 단위 테스트(`eval/PqUpfrontProfileTest`)로 프로필 파일이 `PersonalizedProperties`에 UPFRONT_FOLLOWUP, 이중 요청 꺼짐으로 들어가는 것 확인
  - 실제 서버를 프로필로 띄워 보지는 않음
- 협의 필요(채원): B안을 고르면 첫 질문 로딩 문구를 바꿔야 함. 지금은 12~20초 동안 "건강정보를 확인하고 있어요"만 보임. 프론트는 고치지 않음
- 미결: OSIV 끄기(`spring.jpa.open-in-view: false`)를 반영할지 사용자 답 기다리는 중

## 첫 질문 로딩 문구 + OSIV 끔 반영 (영준, Claude)

- 요청: 설문 관련 프론트는 사용자가 직접 작업 중이라 수정해도 됨, OSIV 커밋해도 됨
- 정정: 앞 블록과 비교 문서에 "B안 첫 질문 대기 중 '건강정보를 확인하고 있어요'만 보임"이라고 쓴 것은 틀림
  - 실제로는 다음 질문 대기 문구가 1.7초마다 바뀌고 "거의 다 만들었어요"에서 멈춤
  - 그래서 답이 없는데 "답변을 살펴보고 있어요"가 나오고, B안에서는 "거의 다 만들었어요"가 10초 넘게 떠 있음
- 변경 파일
  - `frontend/src/recommendation/PersonalizedModal.jsx`
    - 첫 질문 대기 문구를 따로 둠: 건강정보 살펴보기 → 질문 고르기 → 질문 준비, 3초 간격
    - 안내 "10초 정도 걸릴 수 있어요"를 함께 보여 줌
    - 다음 질문 대기는 기존 문구 그대로
  - `backend/src/main/resources/config/recommendation-defaults.properties`: `spring.jpa.open-in-view=false` (Git에 있는 공통 기본값. 각자의 application.yml에 값이 있으면 그쪽 우선)
  - `backend/src/main/resources/application.yml.example`: `open-in-view: false` 1줄 (로컬 application.yml은 Git 제외라 고치지 않음)
  - `docs/design/V2-question-prefetch-options.md` 5장: 로딩 문구 반영 내용으로 고침
- 참고: 테스트용 `src/test/resources/application.yml`에는 STEP 02부터 이미 `open-in-view: false`가 있었음
  - 그래서 10-27 "OSIV 끔 전체 테스트"는 평소 테스트와 조건이 같았음. 새로 확인된 것은 로컬 서버 측정(GET 21개, 부하)뿐
- 보류: 사용 가능 메모리 319MB(Chrome 약 2.5GB)라 서버 기동 확인과 `pnpm build`를 하지 않음 → 확인 전이라 커밋하지 않음
