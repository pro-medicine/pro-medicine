## PR #64 내 영양제 목록·등록·일정 수정·삭제·검색 및 마이페이지 화면 연결 (주연, Claude Code, 이슈 #49)

- 백엔드 (`domain/product`)
  - 목록 `GET /api/v1/users/{userId}/products`: 제품은 `left join fetch`, 일정은 제품 id 목록 IN 조회 → 쿼리 2번(N+1 방지), 복용 중(`is_active`)·켜진 일정(`is_enabled`)만
  - 등록 `POST`(일정 함께 저장), 일정 수정 `PUT /{userProductId}/schedules`(기존 일정 끄고 새로 저장), 삭제 `DELETE /{userProductId}`(`is_active = false`, 204), 제품 검색 `GET /api/v1/catalog-products?keyword=`(최대 20개)
  - 값 검사: 끼니·식전후 코드, 알림 시각, 같은 끼니 중복 → 400 / 남의 것·삭제된 것 → 404(P003) / 중복 등록 → 409(P002)
  - 등록 시 `findWithLockById`로 같은 유저 요청 직렬화(동시 중복 등록 방지)
  - 일정 조회·끄기는 `SupplementScheduleRepository`로 분리, 다른 담당자 파일은 develop 기준 유지
- DB: `schema.sql`에 `user_products`, `intake_schedules` PK AUTO_INCREMENT 추가
- 프론트 (`mypage/`, `api/mypageApi.js`)
  - 마이페이지 tsx → jsx, 목업 대신 API 연결, `MyPage.tsx` 삭제, API 파일을 `src/api`로 옮기고 공용 `client.js`(axios) 사용
  - 영양제 등록·일정 수정 페이지(`SupplementAddPage.jsx`), 카드 수정/삭제 버튼, 섭취 영양제가 없으면 게이지 대신 안내
  - 리뷰 반영: 늦은 목록 응답 무시(`ignore`), 삭제 성공 시 카드 즉시 제거, 편집 부분 저장 시 저장된 항목 표시·닉네임 반영, 수정 화면 빈 일정 허용, 검색 중 Enter 차단, 프로필 편집 버튼 onClick, 410px 이하 그리드 열 축소
  - 내 정보 편집 선택지를 설문 value_code(성별 M/F, 흡연·음주·커피·식단·햇빛, 질환 코드)와 같게 변경
- 확인: 등록·일정 수정·검색 200, 잘못된 값 400, 남의 것 404, 중복 409, 삭제 후 재삭제 404, `npm run build`·eslint 통과, 브라우저에서 마이페이지 API 4개·검색·편집 화면 확인
