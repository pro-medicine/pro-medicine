- `eval.gradle`(로컬 전용) `v2EvalRun`에 `maxHeapSize = '768m'`
- Fake 실험 B 1회(BACKGROUND, 생각 시간 0.5초, 비용 0원), 1초 간격으로 java 프로세스 Working Set 기록 (`--no-daemon`이라 실행마다 일회용 데몬이 뜸)
  - Gradle 데몬 최대 476MB, 테스트 JVM 최대 486MB, 기타 java 2개 112MB·48MB
  - java 합계 최대 **1,049MB**, 실행 중 시스템 사용 가능 메모리 최저 795MB
- 시작 기준: 1,049 + 300 = **1,349MB** (사용 가능 메모리, Available MBytes). 시작 시 1,884MB → R0-B 진행
- 제안만 (적용 안 함): 데몬을 더 줄이려면 사용자 홈 `~/.gradle/gradle.properties`에 `org.gradle.jvmargs=-Xmx512m -XX:MaxMetaspaceSize=256m` (프로젝트 gradle.properties는 팀 공통이라 건드리지 않음)
- 참고: 메모리 기록 스크립트를 `-ExecutionPolicy Bypass`로 실행하려다 권한 확인에서 막혀, 같은 루프를 PowerShell 명령으로 직접 실행함
