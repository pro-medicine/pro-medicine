## SSE 실시간 알림 (응진, Claude, 이슈 #56)

- 설계: SSE는 "새 알림이 생겼다"는 신호만 보내고, 프론트는 기존 API(안 읽은 개수, 목록)를 다시 조회
  - `NotificationService.create()`는 중복 여부를 반환하지 않으므로(#25), 중복이어도 신호를 보내고 프론트 재조회로 처리
- 백엔드
  - `NotificationSseService`: 사용자별 연결(`SseEmitter`, 30분) 보관(`ConcurrentHashMap` + `CopyOnWriteArrayList`, 탭 여러 개 허용), 완료·시간 초과·오류·전송 실패 시 정리 + 단위 테스트 5개
  - `GET /api/v1/notifications/subscribe?userId=` (EventSource는 헤더 불가 → 로그인 연동 전까지 쿼리 사용), 30초 하트비트 스케줄러 + `@WebMvcTest` 2개
  - `create()`에서 `NotificationCreatedEvent` 발행 → `NotificationSseListener`(`AFTER_COMMIT`, `fallbackExecution`)가 받는 사람에게 신호 전송 + 테스트 3개 (`@RecordApplicationEvents`, Mockito)
  - 수동 확인: `curl -N`으로 A·B 구독 → 팔로우 요청·수락·친구 복용 완료 시 받는 사람 창에만 `event:notification`, 409(롤백) 시 신호 없음
- 프론트
  - `subscribeNotifications()`(EventSource) 추가, App에서 구독 → 신호 수신 시 `homeRefreshKey` 증가로 빨간 점·홈·열린 패널 재조회
  - PR #54 잔여 리뷰 반영: 패널을 열자마자 읽으면 개수가 0이 되던 문제(`countChangedRef` 제거, refreshKey 재조회 + ignore로 최신 값만 적용), 개수 조회 실패 시 "모두 읽음" 비활성 문제
  - 화면 확인: 새로고침 없이 빨간 점 켜짐, 패널이 열린 채로 새 알림이 맨 위에 표시, 백엔드 재시작 후 자동 재연결
